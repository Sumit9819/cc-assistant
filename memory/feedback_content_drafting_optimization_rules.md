User set these as permanent rules on 2026-05-13 for all content work on ER of White Rock (and by analogy, any cc-assistant site). They are stored in the WP site_memory Rules section so they survive across sessions, and here so they survive across conversations.

**1. Keyword-optimized — GSC + own knowledge.**
Before writing or optimizing, pull GSC data: gsc_opportunities (position 5-15 with impressions), gsc_page_queries (what this URL currently ranks for), gsc_low_ctr (where the meta is the lever), gsc_cannibalization (own competing pages). Layer your own keyword/SERP knowledge on top. Every post must answer a real, demonstrated search intent — not a guess.

**2. Competitor-beat — find gaps and fill them.**
Run competitor_brief + WebFetch the top 3-5 ranking pages for the target query. Identify what they miss (subtopics, data, depth, structure, schema, citations), then write to fill those gaps and beat them. Never copy; always synthesize. The goal is information gain over the SERP, not parity.

**3. User-first alongside keyword + competitor.**
The post serves the reader first. Keyword and competitor data shape WHAT we cover and HOW we structure it, but the prose, tone, and depth must answer the user's real question better than any competitor. No keyword stuffing. No algorithm-bait. Write for the patient or family member who actually needs this answer.

**4. Unique insight, data, and information gain — expert opinions allowed and encouraged.**
Every post adds something the SERP does not already say. Cite new or under-used statistics (CDC, NIH, AHA, MedlinePlus, peer-reviewed studies). Include practical clinical-workflow insights. **Quote named professionals** (physicians, public-health officials, researchers) by name for E-E-A-T credibility. We do not add our own opinions, but quoting cited expert opinions IS allowed and encouraged. See [[feedback_blog_data_not_opinion]] — that earlier rule banned OUR opinions; this rule clarifies that EXPERT opinions are fine.

**How to apply:**

For NEW posts: brief_for_keyword + competitor_brief + WebFetch top 3-5 → outline → draft → propose_rewrite_outline (if delta will be large) → draft_create_post → verify_change → polylang link if bilingual.

For EXISTING-page optimization: post_dossier + gsc_page_queries + gsc_low_ctr + competitor_brief + find_duplicate_content → propose edits per the 4 rules → queue → verify_change.

**Why:** the user explicitly added these as permanent rules after a multi-week content build where shortcuts on competitor research or "no opinion" interpretation produced shallow posts that didn't differentiate. This rule set codifies the standard going forward.

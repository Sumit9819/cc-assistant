**Two new features, both grounded in problems this project hit:**

1. **`render_probe(id, extract)`** — MCP tool → `GET /posts/{id}/render-probe` → `CC_Assistant_Render_Probe::probe()` in `includes/class-render-probe.php`. Loopback-fetches the post's OWN front end (`wp_remote_get` on the permalink, cache-busted) so it reads the LIVE rendered DOM **bypassing the SiteGround edge WAF** that 403s external curl/WebFetch (see [[reference_siteground_ua]], [[feedback_curl_test_url_before_editing]] — render_probe is now the reliable verify path). Returns: `schema` (every JSON-LD block, attributed to emitter via rank-math class / hand-built-snippet HTML comment banner / cc-assistant meta, linted for **self_serving_rating** on Organization/LocalBusiness/MedicalOrganization/EmergencyService, **breadcrumb_missing_name**, **duplicate_breadcrumb**, **breadcrumb_position_string**, invalid JSON), `links` (resolved accessible name = aria-label > text > child img[alt] > title, so alt'd image links stop reading as empty — fixes the `empty_link` false positive), `images` (alt coverage), `headings` (live h1-h6 outline). Functionally tested: catches the exact 4.9 self-serving rating + breadcrumb-missing-name bugs we hit.

**v0.46.1 — render_probe stale-cache FIX** (zip cc-assistant-0.46.1.zip, 89 files). render_probe's only cache-bust was a query-string param (cc_probe=time()), which does NOT defeat SiteGround's full-page Dynamic Cache (path-keyed, ignores query strings). Result: it silently returned a pre-edit cached page as "live" for a whole verify session (byte-identical 126247 bytes / 155 links every call even after the TOC was enabled). Fix in class-render-probe.php: (1) fetch() now sends Cache-Control: no-cache + Pragma: no-cache request headers (best-effort bypass for caches that honor them) + a stronger microtime/uniqid buster; (2) new cache_state($resp) reads response markers (x-proxy-cache / x-sg-cache / sg-f-cache / x-sg-cdn / x-cache / cf-cache-status / age) → normalized {state: hit|miss|unknown, markers}; (3) probe() returns a `cache` block and, on a HIT, a loud STALE-RISK warning to purge + re-probe. 8/8 detection cases pass. LESSON: SG Dynamic Cache can't be query-string-busted from an anonymous loopback — only the operator purging (or a cache-exclusion) makes the public/crawler HTML fresh; the probe now SAYS so instead of lying. NOTE: render_probe still can't prove a server-injected TOC renders (it returns schema/links/headings/images, not raw HTML or heading ids) — confirm the TOC anchor delta via the link count once cache is purged.

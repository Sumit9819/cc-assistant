When building content for a bilingual site (e.g. erofwhiterock.com with Polylang en+es), do not queue ES and EN versions in the same batch. The reviewer reads only English, so a pending inbox mixing both languages is unreviewable — they cannot tell what a Spanish-titled pending is about without translating it back.

**Workflow:**
1. Draft and queue the **EN post first** (body + slug + RM title + RM desc + cluster + featured image).
2. Let the user review/approve those EN pendings, OR at minimum get explicit go-ahead that the EN version is locked.
3. Then draft and queue the **ES localized rewrite** of the same post.
4. Link them via Polylang once both exist.

**Why:** user said 2026-05-11 "from now on I should see post in english, the spanish version should be made after that, since there I can see spanish post too, it is hard for me to know what is the post about." Mixed-language pending inboxes are unreviewable for a non-Spanish-speaking reviewer.

**How to apply:**
- When user asks for bilingual cluster work, default to EN-first, ES-second across batches — even if it means more sessions or more user approvals along the way.
- If user wants to batch, ask explicitly first.
- For cluster gap-fill tasks like "make all the supporting pages bilingual," interleave by post: post A EN → post A ES → post B EN → post B ES, not "all EN then all ES" and never "all mixed."

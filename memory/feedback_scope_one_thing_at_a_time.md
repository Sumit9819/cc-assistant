When a user requests a multi-step body of work (e.g. "finish pillar 1 cluster, then move to pillar 2"), do NOT bundle a "which pillar next?" question into the same scoping prompt. Drive the current scope to completion first.

**Why:** User explicitly course-corrected on 2026-05-11: "We haven't even finished the current pillar page cluster pages, so lets complete this one and move to next one." Asking about a future pillar while the current one's bilingual gaps are open felt like jumping ahead.

**How to apply:**
- When user lists Task A + Task B, treat B as deferred. Plan + execute A end-to-end. Ask about B only after A's pendings are queued.
- Translation-style / structural choices for A are fine to confirm up front.
- Avoid AskUserQuestion bundles that mix current-scope decisions with future-scope routing.
- "What's next?" can come at the very end, after the current queue is visible to the reviewer.

Operator wants ElementsKit gone, one site at a time, replaced with native Elementor. Chosen: **Lufkin first**, and new header/footer built **unpublished, then switched** (not edited in place).

**Inventory (scanned every published URL: Irving 97, Lufkin 162, White Rock 129, IWC 82; `data-widget_type` in rendered HTML).**
- **White Rock: ElementsKit is NOT installed.** Header 4476 / footer 4486 are Elementor Pro templates using native `mega-menu` (nested), `theme-site-logo`, `social-icons`, `polylang-language-switcher`. Combined CSS 330 KB vs Irving 744 KB / Lufkin 669 KB. This is the working reference that the swap is fine.
- **IWC:** no ElementsKit at all.
- **Lufkin (ElementsKit Lite 4.0.1 active):** Pro header 6221 + Pro footer 6018 (footer already fully native). Only 2 ekit widgets, both in the header: `ekit-nav-menu` (id 3c6d26b1) and `elementskit-social-media` (13c73464, 6 links, rendered as inline SVG so **no icon font is downloaded on Lufkin**). Native `icon-list` (7788b59b) uses ekiticons glyphs (`icon-phone-call1`, `icon-mail`, `icon-location`) and must be swapped to FA5. Menu = WP menu "menu": 5 top items (Emergency Services 21 subs, Resources 2, About Us 7 with one nested level, Careers, Contact Us). **No mega-menu panel renders on Lufkin** (`.elementskit-megamenu-panel` count 0; the 5 hits in HTML are dead rules in Additional CSS). Nav style to match: Roboto 15/400, item spacing 8px, bar height 70, hover underline #ff5e13 2px, active text #FE0467, submenu 280px (200 tablet), toggle border/colour #ff5e13, mobile logo id 4673.
- **Irving (ElementsKit Lite 4.0.1 active):** worst case. Header AND footer are **ElementsKit templates** (`elementskit_template` posts 2038 "MegaHeader", 2224 "MegaFooter", plus 4356 "MegaHeader v2"), not Elementor Theme Builder. Same 2 ekit widgets. Icons are real font glyphs here (phone-call, envelope1, location, 5 socials, menu-11, down-arrow1), covered today by the 4 KB inline subset hack. An unused Pro header template 4150 already exists.
- Both sites also carry `elementskit_content` mega-menu templates 2061 / 2297 (22 service buttons each, identical). Unused on Lufkin.

**Cost of keeping it:** ~98 KB of ElementsKit CSS inside the render-blocking combined stylesheet on each site (measured by summing rules whose selectors mention ekit), plus `jquery.magnific-popup.min.js` 20 KB, plus its framework JS. On Irving it also forces the 454 KB icon font (currently masked).

**Replacements, all verified present on Lufkin via `widget-schema`:** `nav-menu` ("WordPress Menu", reads the same WP menu so all 28 links survive), `social-icons`, `icon-list` with FA5 icons, `theme-site-logo`. Elementor 4.2.3 + Pro 4.0.1/4.2.2 active on all sites.

**Sequence agreed:** duplicate the header template with no conditions -> rebuild the 3 widget swaps in the copy -> point it at ONE page for a visual check -> operator approves -> switch conditions site-wide (old template kept as rollback) -> verify -> deactivate ElementsKit -> re-measure -> delete dead `.elementskit-megamenu-panel` CSS from Additional CSS on all three sites, and (Irving) delete the icon-subset block from `build.py` IRVING_EXTRA.

The plugin can create elementor_library templates with `template_type` + conditions (`class-apply.php::stamp_template_identity`) and already recognises `elementskit_template` / `elementskit_content` post types.

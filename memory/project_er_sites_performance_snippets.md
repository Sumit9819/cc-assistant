Snippets live in `D:\cc-assistant\tools\er-performance-snippets\` (`build.py` assembles `erofirving.php`, `erofwhiterock.php`, `eroflufkin.php` from shared blocks; rebuild after edits). Operator pastes into Code Snippets (none of the ER sites had it on 2026-09-17).

Baseline (US Lighthouse, one run): Irving desktop LCP 1.5 s, mobile FCP 6.3 s / LCP 8.3 s; White Rock desktop 0.72 s, mobile LCP 3.2 s; Lufkin desktop 1.6 s, mobile LCP 9.0 s, CLS 0.227 (CrUX CLS SLOW).

Site facts that decide what is safe:
- **Irving**: child theme `hello-elementor-child` (update-safe) already removes emoji, oEmbed, jQuery Migrate, Dashicons, Gutenberg CSS. ElementsKit icon font `elementskit.woff` 454 KB (WOFF only) loaded on every page for 10 icons (down-arrow1, envelope1, facebook, instagram-1, linkedin, location, menu-11, phone-call, twitter, yelp-1; scanned all 98 published pages/posts). Subset WOFF2 2,164 bytes served as a data-URI @font-face after ElementsKit CSS (wp_head 999); rendered identical to the original. **If anyone adds a new ElementsKit icon it will be blank**: rebuild the subset (fontTools, codepoints from the combined CSS `.icon-x:before{content}`) or delete the block. Hero: desktop `Fast-Expert-Care-scaled.webp`, mobile `ER-of-Irving-Mobile-Background-Image-of-Hero-Section.webp`, switch at 767/768; CC Assistant's cc-hero-preload removed on front page (see [[project-cc-hero-preload-mobile-bg-bug]]).
- **White Rock**: parent Hello Elementor 3.4.7 with ~200 lines of pasted custom code in functions.php (head cleanup, emoji, a WebPage JSON-LD block, header-image meta box, dead Flying Scripts filters and a nonexistent `FlyingScripts.loadNow()` call). A theme update will wipe it; migrating it to a snippet is still open.
- **Lufkin**: parent Hello Elementor 3.4.5 with custom feed-link removal and a feed redirect in functions.php (also wiped by an update). Homepage image attachment 6458 above the H1 on phones was SG-lazy-loaded and pushed the H1 down 348 px (CLS 0.105-0.241); served un-lazied it measured 0-0.004. Lufkin SG excluded classes include `skip-lazy` and `swiper-slide-bg`. Hero is a 3-slide Elementor Slides widget; first slide `Lufkin-Facality.webp` is LCP on phone and desktop. **Flying Scripts holds back nothing on Lufkin**: GTM4WP's `<script data-cfasync="false" data-pagespeed-no-defer>` is not rewritten there (it is on Irving with the same plugin); likely simple_html_dom parse failure; unresolved.
- All three: Flying Scripts 1.2.4, only the GTM snippet is lazy on Irving/White Rock (no menu scripts), so the tag scheduler is safe. Removing jQuery Migrate on White Rock and Lufkin: no JS errors, Lufkin mobile menu still opens (White Rock's mobile menu toggle was not found by the test either way).

**Test trap:** a preload with a `media` query inserted before `<meta name="viewport">` is evaluated against the 980 px default mobile layout width, so phones fetch the desktop image. WordPress prints wp_head output after the theme's viewport tag, so the snippet is fine; put test injections after the viewport meta.

**Live results 2026-09-17 (after paste; US Lighthouse, one run each, before -> after):** Irving desktop LCP 1.5 -> 0.83 s, mobile FCP 6.3 -> 4.1 s, LCP 8.3 -> 5.1 s (remaining: 153 KB combined CSS, ~128 KB unused). White Rock mobile LCP 3.2 -> 3.0 s, SI 5.0 -> 3.1 s. Lufkin desktop LCP 1.6 -> 0.71 s, mobile LCP 9.0 -> 3.2 s, TBT 98 -> 0 ms (GTM now held back there too), CLS still 0.105 because Elementor element cache (TTL 24 h) kept the old image widget HTML; the skip-lazy filter only shows after that cache clears. **Irving's child theme was deleted the same day** (only hello-elementor 3.5.1 installed), so its jQuery Migrate / Gutenberg removals were lost; the MIGRATE_AND_BLOCKS block was added to Irving's snippet (operator must re-paste). Whether the child style.css held design CSS is unknown. Elementor element cache also means any widget-level filter (wp_get_attachment_image_attributes) needs Elementor > Tools > Clear Files & Data before it is visible.

**Round 2 (2026-09-17 afternoon).** Irving: replaced the font-only override with a full swap: `style_loader_tag` blanks handle `elementor-icons-ekiticons` (not in admin or `?elementor-preview`), and a 4,165-byte inline block (subset @font-face + the one base rule + 10 glyph rules, glyphs written as literal characters via html_entity_decode, zero backslashes) prints at wp_head 999. Speed Optimizer's CSS combinator reads the finished HTML, so a tag that never prints never enters the combined file. Verified: PHP output byte-identical to the tested CSS; 13 icons identical (content, font, size, line-height, weight, colour, box) on home, Contact and a blog post, phone and desktop. Removes 83.5 KB uncompressed from the render-blocking combined CSS (863 KB). ElementsKit `ekit-widget-common` (common.css, 202 KB) is the next-largest block but holds the nav menu styles; not touched. Lufkin: `wp_get_attachment_image_attributes` never reached the rendered image (not SG cache: a cache-busted MISS render still lacked the class), so the fix switched to `sgo_lazy_load_exclude_images` (exact src match, runs on final HTML). **White Rock's parent functions.php contains NO Hello Elementor stock code at all** (no setup, stylesheets, title-tag, locations, theme.php); the site renders fine without it (1 title, 1 H1). Updating that theme would bring the stock code back and can change the design: test on staging first. Safety-net snippets `erofwhiterock-theme-code.php` / `eroflufkin-theme-code.php` wrap the custom code in `after_setup_theme` + `function_exists` guards (Code Snippets runs before functions.php, so an unguarded copy would fatally redeclare); PHP harness: 0 hooks added while the theme has the code, all working hooks taken over after removal.

**Round 3 verified live (2026-09-17 evening).** Operator had already updated White Rock's theme to Hello Elementor 3.5.1 before the warning; all three sites now run 3.5.1. White Rock after the update: 1 title, 1 meta description, 1 H1 per page (no Hello page-title block), no JS errors, DOM ~1,067 (was 1,065-1,075), desktop and phone screenshots normal; the safety-net snippet took over (WebPage JSON-LD on inner pages, absent on EN/ES front pages as coded). Hello's automatic feed links now appear on White Rock and Irving (2 rss links); Lufkin keeps them removed via its safety net, and /feed/ still 301s to the page. Irving: ekiticons.css absent from the combined CSS, inline icon block present, big font not requested. Lufkin: image 6458 loads normally (sgo_lazy_load_exclude_images worked). All snippets active, error-free, byte-identical to the files in tools/er-performance-snippets/.

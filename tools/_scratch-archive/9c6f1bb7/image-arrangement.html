Compression

The sources are PNGs between 0.44 MB and 5.7 MB, which is far too heavy for body images. Each one is re-encoded to WebP at 1200px wide, quality 82 — matching the site's existing WebP convention, and 1200 covers a 2× display on the theme's content column without paying for the 1600px the featured slot uses. Originals are never overwritten.

Filenames become <post-slug>-<n>-<description>.webp, so the media library stays greppable by post. Files named only with a number lose the meaningless stem and become <post-slug>-<n>.webp.

Why this runs as a script, not through me

Reading a Slack file hands the bytes to the model as base64. At roughly 3 MB per image across 67 images, that is hundreds of megabytes through a conversation — a single 3 MB image alone is about a million tokens. It cannot be done that way.

The upload endpoint added in v0.77.0 does not need the model in the loop. prepare_images.py reads the files, re-encodes them, and POSTs each one straight to the site using the credentials already in .mcp.json. Only the returned URLs come back to me, and I use those to queue the placements.

  1. Build and install the plugin zip so /assets/upload exists on the live site. The site currently runs 0.76.7.
  2. Download the channel's images into one folder per post slug, named exactly as the cards above. The card lists tell you which files go where.
  3. python prepare_images.py --src <folder> to convert and check the output, then re-run with --upload.
  4. I read uploaded.json, write alt text per image, and queue the in-body placements for approval — in batches of 20.
# trial run on one post first
python prepare_images.py --src D:/slack-images --only low-testosterone-brain-fog

# then the whole batch
python prepare_images.py --src D:/slack-images --upload

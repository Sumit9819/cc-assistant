Category page layout corrected

A spacing fault affecting all 74 category pages, found by measuring the rendered page.

The Divi template that renders category descriptions carries a pillar-text class intended as a styling hook, but no stylesheet on the site defined any rules for it. The result, measured live:

ElementSpace aboveSpace belowLine height
Heading (H2)0px10px26px on 26px type
Sub-heading (H3)0px10px22px on 22px type
List item0px0px—

A heading with no space above it visually attaches to the paragraph before it, so each section ran into the last and FAQ blocks read as a single mass. Body text also ran the full 1192px column, roughly 140 characters per line and about double a comfortable reading measure.

A corrected stylesheet was written and proved by injecting it into the live page and re-measuring rather than judging by eye: heading separation 0 → 32px, list items 0 → 8px, line width 1192 → 900px, with no horizontal overflow at phone, tablet or desktop widths.

Stylesheet faults repaired

Two long-standing bugs found while reviewing the site’s custom CSS.

Wishlist button hover never applied

Repaired

The hover rule contained a stray space, which made it target the elements inside the button rather than the button itself. Those inner elements carry no border width, so the intended highlight never appeared on the page at all.

Invalid animation keyframe

Repaired

The shine animation’s opening frame specified a length with no unit, which browsers discard silently, so the effect began from a different position than intended. Rewritten to be valid while rendering identically to the current behaviour.

Three duplicated rule blocks were merged and two dead declarations removed. Rule order was deliberately preserved, since reordering CSS can silently change which rule wins where specificity ties.

Which add-ons each page genuinely needs

64 URLs were scanned to establish where each Divi add-on is actually in use, rather than assuming.

  • DiviFlash (276.9 KB) is used on the About and Delivery pages and on some product templates. It is not used on the homepage, shop, category pages, blog posts, cart, checkout or account pages — which are the pages organic search traffic lands on.
  • Divi Machine has no standalone module usage, but the lighting product template carries 46 of its specification modules, so product pages require it.
  • BodyCommerce powers the mini-cart, which appears site-wide and is required everywhere.
  • Font Awesome loads 99.8 KB of stylesheet plus a ~110 KB font file from an external server to render the footer payment icons, using 0.4% of it. It is the largest single piece of unused weight that can be removed cleanly.

A tested assumption that proved false

The 787 KB SiteGround bundle loads alongside several other large stylesheets, which suggested the same CSS might be shipping twice. That was tested directly: only 1–2% of selectors overlap. They are not duplicates, and the bundle needs per-plugin analysis before any hosting setting is changed.

Method. Every figure in this report was measured against the live site rather than estimated — rendered page measurements for the layout work, and browser coverage instrumentation for the stylesheet audit. Coverage records what a page uses as it renders, so rules for hover states and other screen sizes register as unused; the figures therefore describe the scale of the opportunity rather than a list of rules that can simply be deleted.

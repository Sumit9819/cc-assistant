# CC Assistant reliability update — 0.83.0

The live site was verified on 0.82.0. This additional release implements safeguards requested after that installation. It changes local plugin source, the local MCP bridge, Claude Code hooks and workspace guidance, and provides a new uploadable ZIP. It does not deploy 0.83.0 or edit live pages.

## Confirmed live setup

Read-only checks through the configured browser transport succeeded for `whoami`, `gsc_status` and `list_installed_plugins` on erofwhiterock.com. Search Console is connected to `https://erofwhiterock.com/`, reported 5,791 cached rows, last sync `2026-09-08T04:03:58+00:00`, and no last error. This is a connection check, not an assessment that all pages are indexed or SEO is correct.

The active stack includes Elementor 4.2.3, Elementor Pro 4.0.2, Rank Math SEO 1.0.276, Polylang 3.8.7 and Speed Optimizer 7.8.1. A separately connected direct MCP client still encountered a SiteGround challenge. That client does not automatically inherit the local browser transport configuration. No site-wide CAPTCHA protection was disabled.

## What was fixed or added

1. **Repeatable page assessments.** New `verified_page_audit` uses fixed, versioned rules and includes exact observations, UTC time, URL, HTTP/cache state and fingerprints. It compares the latest report with the previous report. Same inputs produce the same findings. Findings are pass, fail, review, unknown or not applicable; the report cannot declare overall SEO perfect.
2. **Old facts cannot masquerade as current verification.** Interactive page-facts reads refresh by default. A new capture invalidates the older after-apply verdict. Failed refreshes explicitly return stale evidence without verification. Capture persistence failures are surfaced. The seven-day background inventory remains available only through explicit cached reads and background operations.
3. **Bad fetches are not page evidence.** Both fact capture and legacy render probes reject HTTP errors, redirects, non-HTML and recognized CAPTCHA pages. TLS verification is enabled. A cache HIT cannot produce a usable current audit, and unknown/HIT cache freshness cannot verify the newest write. Unknown cache state remains visible on otherwise usable HTML observations.
4. **More accurate SEO observations.** Counts expose duplicate title/description/canonical tags. Robots checks include Googlebot meta and X-Robots-Tag. Empty decorative alt differs from missing alt. Commented-out JSON-LD is excluded. Bounded link/text observations cannot prove absence and now produce an inconclusive after-apply result when appropriate.
5. **Invalid Elementor settings are blocked.** The supported update-widget/add-widget/add-container draft paths now return HTTP 422 for unsupported settings, invalid choices, incompatible value shapes, unavailable responsive variants, disabled gates and retained global overrides. Defaults-only creation remains valid. The runtime schema is no longer cached across requests, and full choice lists are preserved. These checks do not yet cover all nested imports, rebuilds or mutation types.
6. **Plugin discovery has explicit limits.** Results identify the installed version, observation time and provenance. Unknown features, licensing and effective behaviour stay unknown. Stored settings and prefix matches are no longer presented as a complete capability list.
7. **Safer generic setting plans.** `allow_create=true` alone cannot invent an option path: an explicit registered REST schema is also required. Registered values are validated when available. Both dry runs and queued responses expose whether only storage or a schema was verified. Credential-shaped leaf paths are refused. Apply checks the option snapshot and reads back the actual result; rollback refuses newer changes and reports failed restoration instead of always reporting success.
8. **Local Claude enforcement.** Identity/page evidence expires after ten minutes; failed newer reads invalidate older proof. Updated sites require the new audit before the listed render-affecting mutations. Older sites retain a checked legacy path; drafts use editor data. Generic setting drafts require recent discovery of the specific option. These hooks apply to this Claude Code workspace, not independently configured MCP clients.
9. **Removed misleading certainty.** Four legacy scoring tools now label their descriptions and MCP results as heuristic. Their local scores are not Google scores or proof a page is defective. Workspace guidance now follows the evidence workflow and the integrated browser connection, replacing unsupported blanket explanations of SiteGround challenges.

## What remains for installation

1. Upload `D:\cc-assistant\dist\cc-assistant-0.83.0.zip` in WordPress and replace the existing CC Assistant plugin. The newly added server tool requires this update. Prefer a staging copy first for a real WordPress/Elementor integration check.
2. Restart Claude Code/MCP so it reloads the local 0.83.0 bridge and hook. Run `whoami` on erofwhiterock.com; verify both ends report 0.83.0, then run `verified_page_audit` twice for the same published page. Stable evidence should return unchanged findings. Review collection failures rather than treating them as an SEO failure.
3. Exercise one normal Elementor and one Rank Math draft on staging: read evidence, inspect controls, dry-run, review the queued change, approve in wp-admin, inspect actual output, then test rollback. No live test edit was made here.
4. Finish the earlier credential improvement: use a dedicated CC Assistant Operator account/application password. Verify its read/propose workflow before revoking the old administrative credential. No credentials or accounts were changed by this update.

## Recommended next additions

**First: deeper validation for the actual installed plugins.** Build version-aware adapters for Rank Math metadata/robots/schema templates, Polylang translations/hreflang, Elementor Kit/repeaters/templates and SiteGround caching. Each should list supported actions, accepted values, defaults, prerequisites, license/feature availability when observable, and how to verify the real effect. Unknown adapters must report unsupported/unverified. Extend validation to nested imports and all mutation paths, revalidate at approval, and bind plans to evidence fingerprints. Keep fixtures from real failures and re-run them after plugin updates.

**Second: an SEO evidence report combining existing tools.** Search Console is already connected. Join its URL Inspection data with the new page audit while displaying separate capture times. Include Google-selected versus declared canonical, last crawl, indexing restrictions, sitemap membership, redirects and broken internal destinations. Inspection reports Google's indexed information rather than a live re-crawl, so a recent edit can legitimately differ: see [Google's URL Inspection API explanation](https://developers.google.com/search/blog/2022/01/url-inspection-api).

**Third: scheduled regression monitoring.** Establish a baseline for important pages, run bounded scheduled checks, and alert on newly changed evidence rather than repeatedly inventing a fresh list of recommendations. Add mobile/desktop browser captures for layout, lazy-loaded content, navigation, forms and accessibility. Separate laboratory performance checks from real-user Core Web Vitals using [Google's guidance](https://developers.google.com/search/docs/appearance/core-web-vitals). Keep browser profiles, locale and viewport consistent and distinguish missing measurements from passing measurements.

**Fourth: meaningful content and business review.** Review emergency-service details, hours, locations, claims and medical information for accuracy with an appropriate subject-matter reviewer. Measure important page/query trends and actual conversion outcomes. Do not rewrite, delete or noindex a page just because a local score is low. Structured-data checks should examine visible content and eligibility; even correct markup does not guarantee a rich result under [Google's structured-data policies](https://developers.google.com/search/docs/appearance/structured-data/sd-policies).

**Further engineering work:** signed releases, stronger resource locks/idempotency for concurrent operations, recovery UI, and separating shared operator knowledge from site-specific private memory remain useful from the earlier review. Review whether powerful maintenance plugins such as WP File Manager are still needed, without removing a working dependency automatically.

## Limits and validation

This release reduces specific routes through which stale evidence and invented settings became accepted work. It cannot guarantee Claude will never hallucinate in its own prose or through another client. Generic plugin storage cannot reveal every feature, license entitlement or runtime effect. Current Elementor validation is deliberately scoped; template/import/rebuild and other mutation paths still need separate validation. Snapshot checks are not a global transaction against third-party concurrent writes.

Validation passed: 154 PHP syntax checks; all 33 standalone PHP test files; isolated Python hook regression; Node syntax; token handling with and without OpenSSL; offline MCP startup and discovery of 164 tools on bridge version 0.83.0. New fixtures exercise repeated audits, changed evidence, CAPTCHA/503/non-HTML/cache failures, missing versus empty alt, commented schema, truncated absence checks, schema drift, invalid controls/values, unknown key creation, stale plans, filtered writes and failed rollback. No PHP runtime warnings were reported by the verification runner.

These are standalone tests with WordPress/Elementor/HTTP/storage doubles, not a full WordPress/MySQL production integration test. The live checks used the installed 0.82.0 plugin; 0.83.0 still needs uploading before its new endpoint can be exercised there. See `wp-content/plugins/cc-assistant/EVIDENCE.md` for the tool contract.
